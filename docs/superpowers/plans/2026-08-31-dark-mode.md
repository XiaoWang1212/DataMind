# 深色模式 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 讓 DataMind 全站支援深色模式，使用者可以在側邊欄一鍵切換，首次進站跟隨系統偏好。

**Architecture:** 深色是「第二組 token 值」而不是「第二套樣式」。`styles/tailwind.css` 的角色 token 已經全部指向 `rgb(var(--v-theme-*))`，所以主體工作是在 `plugins/vuetify.ts` 補一組 `dark` 色票，再把三處寫死顏色的地方（頁面漸層、玻璃材質、元件層的 `rgba()` / hex / `color-mix(…, white)`）改成吃變數。元件檔不會有任何 `@media (prefers-color-scheme)` 或 `.v-theme--dark .foo` 分支。

**Tech Stack:** Vue 3 `<script setup lang="ts">`、Vuetify 4 主題系統、Pinia、Tailwind 4（`@theme static`）、Sass。

**Spec:** `docs/superpowers/specs/2026-08-31-dark-mode-design.md`

## Global Constraints

- **沒有自動化測試。** 前端沒有測試框架，`backend/scripts/test_*.sh` 是手動 curl smoke test，與本計畫無關。每個 Task 的驗收關卡是：型別檢查 + lint 不退步 + 指定畫面的雙主題目視確認。
- **型別檢查指令**（在 `frontend/`）：`npx vue-tsc --noEmit -p tsconfig.app.json`。通過的定義是**沒有任何輸出**。
- **Lint 指令**（在 `frontend/`）：`npm run lint`。**這個專案的 lint 基準是壞的** —— 動工前先跑一次記下總數（2026-08-31 於 `9247aab` 量到的是 `769 problems (766 errors, 3 warnings)`）。關卡是「數字沒有變大」，不是「零錯誤」。
- **不要跑 `npm install` / `npm ci`。** 這個 repo 的 lockfile 有 tiptap peer 衝突會失敗，`node_modules` 已經存在，直接用。
- **開發環境**：`docker compose up -d`（repo 根目錄），前端 http://localhost:5173，後端 http://localhost:5001。Vite HMR 會吃到改動，不需要重啟容器。
- **語言**：使用者可見文字、註解、文件一律繁體中文。變數名、commit message 用英文。
- **註解風格**：平實直述、精簡、一律 `//`（CSS 用 `/* */`）。講「避免 X」不講「不然會 X」。不要寫重述程式碼的註解。

- **淺色模式不得有任何視覺改變。** 這是每個 Task 的硬性驗收條件：所有替換都必須在淺色下產生與原本完全相同的結果。`--color-surface` 在淺色主題是 `#FFFFFF`，所以 `color-mix(…, white)` → `color-mix(…, var(--color-surface))` 是等價替換。

**Files:**

**Interfaces:**

- Produces: `useThemeStore()`，暴露 `mode: Ref<'light' | 'dark'>`、`isDark: ComputedRef<boolean>`、`toggle(): void`、`init(): void`。Task 3 的側邊欄開關會用 `toggle()` 與 `isDark`。

- [ ] **Step 1: 建立 `frontend/src/store/themeStore.ts`**

寫法對齊 `store/authStore.ts`：`defineStore` + setup 風格。

這個 store 只管狀態，不碰 Vuetify —— `useTheme()` 只能在 setup 期間呼叫，而 `toggle()`
會從按鈕的 click handler 呼叫，那時候已經不在 setup 裡了。套用主題的責任交給 `App.vue`。

```ts
import { defineStore } from 'pinia'
import { computed, ref } from 'vue'

export type ThemeMode = 'light' | 'dark'

const STORAGE_KEY = 'datamind:theme'

export const useThemeStore = defineStore('theme', () => {
  const mode = ref<ThemeMode>('light')

  const isDark = computed(() => mode.value === 'dark')

  // localStorage 有值代表使用者親手選過，優先於系統偏好。
  // 不監聽系統偏好的後續變化：選過之後系統再變，不該蓋掉使用者的選擇
  function resolveInitialMode (): ThemeMode {
    const stored = localStorage.getItem(STORAGE_KEY)
    if (stored === 'light' || stored === 'dark') return stored
    return window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light'
  }

  function init (): void {
    mode.value = resolveInitialMode()
  }

  function toggle (): void {
    mode.value = mode.value === 'light' ? 'dark' : 'light'
    localStorage.setItem(STORAGE_KEY, mode.value)
  }

  return { mode, isDark, init, toggle }
})
```

  --glass-fallback: rgba(255, 255, 255, 0.96);

  --glass-menu-tint-from: rgba(255, 255, 255, 0.88);
  --glass-menu-tint-to: rgba(255, 255, 255, 0.78);
  --glass-menu-edge: rgba(255, 255, 255, 0.6);
