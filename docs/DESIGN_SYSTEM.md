# DataMind Design System 視覺規範

> 這份文件是 DataMind 前端的**視覺設計規範(design spec)**,定義「我們的介面長什麼樣、為什麼這樣、規則是什麼」。
>
> **它不是實作指令。** 它不規定要改哪個檔案的哪一行。實作方式(要不要改 Vuetify 主題、token 放哪、用什麼 class)由開發者或 Claude Code 讀完規範後**自行判斷**。文件中出現的「實作提示」只是方向建議,不是硬性規定。
>
> 適用對象:團隊成員、Claude Code。任何人要開發或修改 DataMind 的 UI,先讀這份。

---

## 0. 技術脈絡(現況)

目前前端為 **Vuetify 4 + Tailwind CSS 4 並存**,靠 CSS layers 排優先權:

- Vuetify 4 負責元件與互動邏輯,`vuetify.ts` 定義 light theme 色票與 breakpoints,關閉內建 utilities(`utilities: false`)
- Tailwind 4 負責 utility(版面/間距),CSS-first config,用 `@theme` 把 Vuetify 的 CSS 變數橋接成 Tailwind `--color-*` token → **色彩與圓角是單一 source of truth**
- Layer 排序:`vuetify-core → vuetify-components → vuetify-overrides → vuetify-utilities → tailwind → vuetify-final`
- 字型 Roboto / Roboto Mono,圖標 `@mdi/font`

> 本次改版會大幅調整視覺層。是否重寫 Vuetify 主題、token 如何落地,交由實作者判斷,但**必須維持「色彩/圓角單一 source of truth」這個原則**,不要退化成兩套各自維護的色票。

## 1. 設計原則(判斷基準)

當規範沒有明講、需要臨場判斷時,回到這五個原則:

1. **內容為主,介面退位(Deference)** — 邊框、色塊、裝飾都是為了襯托資料(論文、欄位、分析結果),不跟內容搶注意力。有疑慮時,選更安靜的做法。
2. **清晰優先於美觀(Clarity)** — 任何視覺效果(玻璃、動畫、低對比)一旦犧牲可讀性就是失敗。文字對比至少符合 WCAG AA(一般文字 4.5:1、大字 3:1)。
3. **用層次建立引導(Depth)** — 用「前景/背景、陰影、玻璃、動畫」幫使用者理解「現在在哪一層、什麼重要」,而不是把所有東西平貼在同一平面。
4. **一致性可被學習** — 同一種元件、同一種互動,行為到處都一樣。使用者學一次,整個系統都會用。這是「設計系統」跟「一堆好看畫面」的根本差別。
5. **克制** — 「太雜」永遠比「太簡單」更常出問題。玻璃、強調色、動畫都是稀缺資源,只用在真正需要的地方。

## 2. 色彩系統

### 2.1 核心理念

- **藏青(navy)是品牌身份色**,用在主要動作、選中狀態、logo、重點圖示。它是整個系統的識別,不要讓其他同等飽和度的顏色跟它搶。
- **狀態色(綠/琥珀/紅)只表達「語意」**,不作裝飾。綠=成功/已對應、琥珀=待確認/警示、紅=錯誤/未對應。不要因為「想加點顏色」而用它們。
- **中性灰階**承載絕大多數的文字、邊框、背景。

### 2.2 色票(語意角色 → 建議值)

> 這裡定義「角色」與建議色值。實作時橋接成單一 token 來源(延續現有 Vuetify↔Tailwind 橋接模式)。色值可微調,但語意角色不要亂用。

| 角色 token | 建議色值 | 用途 |
|---|---|---|
| `--color-ink` | `#1A3159` | 主品牌藏青。主要按鈕、選中、重點 |
| `--color-ink-strong` | `#12244A` | 深一階,hover/按下、標題強調 |
| `--color-ink-soft` | `#626B7E` | 次要文字、說明、icon |
| `--color-text` | `#1C2130` | 主要內文 |
| `--color-surface` | `#FFFFFF` | 卡片、面板底 |
| `--color-surface-alt` | `#F6F5F2` | 次級底(表頭、hover 背景、工具列) |
| `--color-page` | `#E4E9ED` | 頁面底(玻璃漸層的基底,見 §5) |
| `--color-border` | `#E4E6E8` | 一般分隔線(hairline) |
| `--color-border-strong` | `#D3D8DC` | 強調分隔、輸入框邊界 |
| `--color-success` | `#1F7A44` | 已對應/成功(圓點);文字用 `#176B39` |
| `--color-success-bg` | `#DCEDE3` | 成功徽章底 |
| `--color-warning` | `#C9822E` | 待確認/警示(圓點);文字用 `#8F560A` |
| `--color-warning-bg` | `#F5E9D8` | 警示徽章底 |
| `--color-danger` | `#C7392E` | 未對應/錯誤(圓點);文字用 `#B8342A` |
| `--color-danger-bg` | `#F5DEDC` | 錯誤徽章底 |

> **重要:金色已淘汰。** 早期版本曾用亮金色當強調色,已確認不採用。琥珀(`--color-warning`)只作狀態色,不當品牌強調。
>
> **圓點色跟文字色刻意不同一個值。** 圓點是實色小面積,直接用 `--color-success`/`--color-warning`/`--color-danger` 沒問題;但文字疊在對應的 `-bg` 淺色徽章底上時,同一個值對比不夠(量過只有 4:1 上下),所以文字一律用表中標的更深值,確保跟徽章底過 §2.4 的 WCAG AA 4.5:1。之後要調任何狀態色,記得兩個值一起檢查對比,不要只改圓點色。

### 2.3 Workflow 節點配色(分類色,非深淺)

Workflow 節點屬於「不同**功能類型**」的節點(類似 Orange ML pipeline),因此**每一類用一個顏色**,而非同色深淺。顏色仍與整體語意掛勾:

| 節點類型 | 建議色值 | 說明 |
|---|---|---|
| 資料(輸入/輸出) | `#5B7A9D` 石板藍 | 資料相關節點 |
| AI / 模型分析 | `#6B5B95` 紫 | Gemini 分析、模型運算等 |
| 人工確認 | `#C9822E` 琥珀 | 需人工介入(對齊 warning 語意) |
| 完成 / 通過 | `#1F7A44` 綠 | 終點、成功(對齊 success 語意) |

> 節點是圓形 + 白色 icon,節點間用連接線串起(見 §7.6)。若未來節點類型變多,新增顏色須避開與狀態色語意衝突,並在此表登記,不要各畫面各自上色。

### 2.4 對比要求

- 文字/背景對比一律過 WCAG AA。
- 低飽和背景(玻璃、淺色底)上的文字,寧可加深文字或加半透明底襯,**不要靠文字陰影(text-shadow)**救對比 — 本專案明確不使用文字陰影。

## 3. 字體

- 介面字型:Roboto(延續現有 `unfonts.css`);中文採系統思源/Noto Sans TC fallback。
- 等寬:Roboto Mono(程式碼、欄位名 `age`、`bmi_score` 等 identifier)。
- 只用兩種字重:**Regular 400** 與 **Medium 500**。不用 600/700 — 過重會與安靜的整體調性衝突。

| 角色 | 大小 | 字重 |
|---|---|---|
| 頁面標題 h1 | 22px | 500 |
| 區塊標題 h2 | 18px | 500 |
| 小標 h3 | 15–16px | 500 |
| 內文 | 14px | 400 |
| 次要/說明 | 13px | 400 |
| 標籤/徽章 | 11–12px | 400–500 |

- 一律**句首大寫(sentence case)**,不用 Title Case、不用全大寫。
- 欄位名、type、class 等 identifier 用 mono 字體,不用粗體強調。

## 4. 間距、圓角、陰影

### 4.1 間距

以 4px 為基準。垂直節奏用 rem(1rem / 1.5rem / 2rem),元件內部間距用 px(8/12/16)。

### 4.2 圓角

圓角語彙與 Vuetify `--radius-*` 對齊。整體偏收斂,**不要過圓**:

| token | 值 | 用途 |
|---|---|---|
| `--radius-sm` | 8px | 按鈕內元素、小 chip、workflow 節點方塊 |
| `--radius-md` | 12px | 卡片、面板、表格容器 |
| `--radius-lg` | 16px | 大型容器(視需要) |
| pill | 999px | 膠囊按鈕、徽章、輸入框 |

### 4.3 陰影

陰影用來表達層級,不是裝飾。統一光源方向(由上往下),色調帶一點藏青而非純黑:

| token | 值 | 用途 |
|---|---|---|
| `--shadow-card` | `0 2px 10px rgba(14,30,66,0.06)` | 一般卡片、表格 |
| `--shadow-float` | `0 16px 40px rgba(14,30,66,0.16)` | 浮動玻璃面板、彈窗 |

## 5. 玻璃效果(Glassmorphism)規範

玻璃是這套系統的特色,但**最容易做壞**。核心規則:

### 5.1 三個必要條件(缺一玻璃就失效)

1. **背後要有東西透出來** — 玻璃層下方必須有漸層色塊/彩色光斑的環境,否則模糊等於白做,只剩一個半透明方塊。頁面底(`--color-page`)應鋪一層柔和的多點徑向漸層(藏青為主、極少量暖色點綴),見 §5.4。
2. **半透明 + 模糊並存** — 只有模糊沒有透明,或只有透明沒有模糊,都不是玻璃。
3. **文字要有底襯** — 玻璃層要疊一層 10–30% 的白色/深色 tint,讓文字對比足夠。

### 5.2 參數建議

- 模糊值 **10–16px** 就好(busy 背景可到 20px 上限)。過高會糊、傷效能。
- 玻璃底 tint:淺色玻璃用 `rgba(255,255,255,0.4~0.7)`;深色玻璃(側邊欄)用 `rgba(16,32,66,0.5~0.7)`。
- 邊框:上緣用較亮的 `rgba(255,255,255,0.6~0.85)`模擬受光邊,其餘 `rgba(255,255,255,0.5)` 左右。
- 一律加 `-webkit-backdrop-filter` 前綴,並提供 `@supports` fallback(不支援時退回較高不透明度的純色底)。

### 5.3 用在哪(克制原則)

玻璃**只用在少數浮動/導覽性元件**,不是整頁玻璃化:

- ✅ 側邊欄(浮在漸層背景上)
- ✅ AI 對話面板(浮動、需要與背後內容區隔)
- ✅ 彈窗 / modal / 浮動工具列(如有)
- ✅ 下拉選單 / select 選單(浮在觸發元件上方的選項清單,屬於「浮動」的一種)
- ❌ 一般資料卡片、表格、內文區塊 — 用實色 `--color-surface`,不要玻璃

### 5.4 背景漸層(讓玻璃可見的關鍵)

頁面底建議鋪多點徑向漸層,提供玻璃透光的顏色來源。範例(可調):

```css
body {
  background:
    radial-gradient(720px circle at 8% 30%,  rgba(90,130,190,0.45), transparent 55%),
    radial-gradient(560px circle at 88% 18%, rgba(110,143,178,0.20), transparent 55%),
    /* 純裝飾暖色點,刻意不用 --color-warning(#C9822E)— 狀態色不進背景,避免語意混淆 */
    radial-gradient(520px circle at 25% 92%, rgba(196,150,130,0.10), transparent 55%),
    linear-gradient(175deg, #EEF2F5 0%, #DCE3E9 100%);
  background-attachment: fixed;
}
```

> 側邊欄若要有明顯玻璃感,把其中一個徑向漸層的亮色塊「放在側邊欄後方」的位置(如左側 `8% 30%`),讓顏色從玻璃透出來。
>
> **暖色點的色值跟狀態色系無關**,不要為了方便直接借用 `--color-warning` 或其他語意色的 hex——那樣一旦之後改狀態色,背景會跟著意外變色,也違反 §2.1「狀態色只表達語意,不作裝飾」的原則。

## 6. 動畫 / Motion 規範

動畫目的:讓系統**流暢、有回饋、有引導**,不是炫技。每個動畫都要能回答「它幫使用者理解了什麼」。

### 6.1 Motion tokens

統一時長與緩動,不要每個元件各自定義:

| token | 值 | 用途 |
|---|---|---|
| `--dur-fast` | 120ms | hover、顏色變化、小回饋 |
| `--dur-base` | 200ms | 一般狀態切換、展開收合 |
| `--dur-slow` | 320ms | 頁面/面板切換、較大位移 |
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | 大多數進場(快進慢出,俐落) |
| `--ease-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | 位移、morph |
| `--ease-spring` | `cubic-bezier(0.34, 1.56, 0.64, 1)` | 需要一點彈性回饋時(節制使用) |

### 6.2 各情境規範

**Hover / 點擊回饋**
- 按鈕、卡片、節點 hover:`--dur-fast`,輕微上浮(`translateY(-1~2px)`)或亮度變化。
- 點擊(`:active`):`scale(0.96~0.98)`,給實體按壓感。
- 統一原則:同類元件用同一種回饋,不要一個按鈕上浮、另一個變色。

**按鈕邊緣反光(specular hover)**
- 全系統按鈕共用同一套 hover:反光沿**邊框細線**跟隨滑鼠移動,按鈕表面底色不變。
- 這是「一致的互動語言」— 不論按鈕底色,反光的「行為」都一樣。
- 實作提示:用遮罩(mask-composite)讓漸層只顯示在邊緣;JS `pointermove` 更新 `--mx/--my` CSS 變數控制光點位置;可加 proximity 感應(滑鼠靠近才亮)。
- 平常狀態邊框須**完全透明無殘留**(避免漏出一圈底色)。

**展開 / 收合(側邊欄、accordion、workflow 詳情)**
- 寬/高變化:`--dur-base` + `--ease-in-out`。
- 側邊欄收合時,文字 `opacity` 先淡出(`--dur-fast`),寬度再收,避免文字被硬切。

**頁面 / 面板切換**
- 進場:`--dur-slow` + `--ease-out`,輕微上移淡入(`translateY(6~8px)` + `opacity 0→1`)。
- 列表項目可加 stagger(每項延遲 30~40ms 依序進場),但總長不超過 ~250ms,避免拖沓。

**狀態變化(對應成功、載入完成)**
- 徽章/圓點狀態改變時給一次性的輕微強調(如 `scale` 一下或淡入),讓使用者注意到變化。
- 載入用 skeleton(骨架屏)而非空白轉圈,維持版面穩定。

**AI 串流 / 打字**
- AI 回覆逐字/逐段淡入,不要整段瞬間跳出。

### 6.3 效能與可及性

- 玻璃 + 動畫同時作用時,避免同時 animate 多個 `backdrop-filter`(會卡)。
- 大位移用 `transform` / `opacity`(可 GPU 合成),避免 animate `width`/`top` 等觸發 reflow 的屬性(展開收合除外,量小可接受)。
- **必須支援 `prefers-reduced-motion`**:偵測到時關閉非必要動畫。

```css
@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important; }
}
```

## 7. 元件規格

> 以下定義每個元件的「規則與狀態」。具體用 Vuetify 元件改、或自刻,由實作者判斷;重點是產出的結果符合這裡的規範。

### 7.1 按鈕

四種變體,**共用同一套邊緣反光 hover**(見 §6.2),差異只在底色:

| 變體 | 底色 | 文字 | 用途 |
|---|---|---|---|
| primary | `--color-ink` | 白 | 主要動作(每個畫面最多一個) |
| secondary | `--color-surface` | `--color-ink` | 次要動作 |
| ghost | 透明 | `--color-ink-soft` | 輕量動作(略過、取消) |
| danger | `--color-danger-bg` | `--color-danger` | 破壞性動作(移除對應) |

- 形狀:pill(999px)。
- `:active` 一律 `scale(0.96)`。
- 每個畫面最多一個 primary,其餘用 secondary/ghost。
- secondary/ghost 在白底上若邊界不清,可加一條極淡的**非彩色** hairline 界定範圍(不是彩色圈)。

### 7.2 側邊欄

- 可收合/展開(寬 220px ↔ 72px),收合動畫見 §6.2。
- 深色玻璃(見 §5.2),浮在漸層背景上。
- **可讀性優先**:靠底色不透明度(0.5~0.7)保證對比,**不用文字陰影**。
- 選中項:較亮的半透明白底 + Medium 字重。
- hover:輕微背景變化,`--dur-fast`。

### 7.3 卡片 / 面板

- 一般卡片:實色 `--color-surface`,`--radius-md`,`--shadow-card`。**不玻璃化。**
- 浮動面板(AI chat 等):玻璃(見 §5)。
- 卡片內列表 row:hover 換 `--color-surface-alt` 底。

### 7.4 資料表格

DataMind 有大量表格,規範:

- 容器:`--color-surface` + `--radius-md` + `--shadow-card`,`overflow: hidden` 讓圓角吃到邊。
- 表頭:`--color-surface-alt` 底,`--color-ink-soft` 文字,12px,Medium。
- 儲存格:14px,`--color-text`,底線 `--color-border`。
- row hover:`--color-surface-alt`。
- 狀態欄用徽章(見 §7.5)。
- 欄位名等 identifier 用 mono 字體。
- 欄多時考慮 `table-layout: fixed` + 明確欄寬,或允許水平捲動。

### 7.5 狀態顯示(徽章 / 圓點)

兩種呈現,依情境選:

- **圓點 + 文字**:資訊密度高的地方(表格、列表)。圓點 8px,實色狀態色,文字用對應深色。
- **徽章 pill**:需要更明顯時。底用 `--color-*-bg`,文字用對應狀態色。

語意固定:綠=已對應、琥珀=待確認、紅=未對應。**不要用狀態色做非狀態的裝飾。**

### 7.6 Workflow

- 節點:圓形(64px 上下)+ 白色 icon,依**類型**上色(見 §2.3)。
- 節點下方放 label(12px,`--color-ink-soft`)。
- 節點間用連接線(2px,`--color-border-strong`)串起,線在節點下層。
- hover:節點 `translateY(-2px)`,`--dur-fast`。

### 7.7 論文編輯區

- 工具列:`--color-surface-alt` 底,工具鈕 hover 換淡藏青底。
- 內文區:充足留白,`line-height` 1.6~1.7。
- 載入用 skeleton line。

### 7.8 文獻參考

- 列表形式,每筆:`[index]` + 作者 + venue。
- index、venue 用 `--color-ink-soft`,作者用 `--color-text`。

## 8. 響應式 / 版面寬度(RWD)

**現況問題**:各頁面各自寫 max-width / breakpoint(760px、80%、88%、1260px…各頁不一樣),窄螢幕還堪用,但螢幕夠寬時內容被拉到滿版,頁面之間比例也對不齊。這節把規則收斂成一份,不要各畫面各自決定。

### 8.1 斷點

沿用 `vuetify.ts` 既有的 `display.thresholds`,不要另開一套斷點系統:

| 斷點 | 寬度 |
|---|---|
| xs | 0 |
| sm | 600px |
| md | 840px(`mobileBreakpoint`,小於此視為行動裝置版面) |
| lg | 1145px |
| xl | 1545px |
| xxl | 2138px |

### 8.2 內容寬度上限(解決「太寬」的關鍵)

版面容器一律有寬度上限,超過就**置中、兩側留白**,不要讓卡片、表格、表單無限拉伸到瀏覽器邊緣。依內容型態分三級,實作時比照色彩/圓角橋接成 token,不要每頁各寫一個數字:

| token | 建議值 | 用途 |
|---|---|---|
| `--content-measure` | 760px | 純文字閱讀區(論文內文、長文說明)。控制單行字數,過寬會難讀 |
| `--content-max-width` | 1280–1440px | 一般頁面容器(表單、Hub 詳情頁、設定) |
| `--content-max-width-wide` | 1680px | 資料密集頁(大型表格、多欄卡片、workflow 外框) |

> workflow 畫布本身如果是可縮放/可捲動的無限畫布,不受此限——這裡限制的是畫布「外面」的頁面殼(頂部工具列、side panel 等容器)。

### 8.3 斷點下的行為

- **< md(840px)**:側邊欄預設收合或改抽屜(overlay)開合;多欄 grid 改單欄堆疊;字級/間距可視情況降一階。
- **md–xl**:標準單欄或雙欄版面,元件依 §7 規格呈現。
- **≥ xxl(2138px)**:不要讓 grid 欄數或卡片寬度隨螢幕無限放大——鎖住 §8.2 的寬度上限,多出來的空間單純留白,不要靠拉伸元件本身撐版面。

## 9. 使用這份文件

- **新增/修改任何 UI 前**,先確認符合 §1 原則與相關元件規格。
- **色彩、圓角維持單一 source of truth** — 不要在個別元件硬寫色值,一律引用 token。
- **新增顏色/元件**時,回來更新這份文件(尤其 §2.3 節點色表),讓它持續是唯一真相。
- 規範沒寫到的臨場狀況,用 §1 的五個原則判斷,選更安靜、更一致、更可讀的那個做法。
